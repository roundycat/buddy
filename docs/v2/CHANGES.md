# Beddy 2.0 — v1 대비 변경 내역

v1(브랜치 `v1`, 커밋 `79ba316`)은 2026 강원 LRS 공유대학 AWS 해커톤 5조 *각양각색*(김기훈·김예인·최유경·하시은)의 결과물입니다.
v2는 원작 팀원 최유경이 새 팀 YSA(대표 정하민 · 최유경·최유현·최태웅)와 함께, 2026 AI 라이프 솔루션 챌린지를 위해 v1 위에 새로 한 탐구개발입니다.
모든 항목은 `git log v1..main`으로 커밋 날짜와 함께 확인할 수 있습니다.

## 탐구 질문

**아이에게 안전한 AI 친구를 만들려면, v1의 안전·프라이버시 장치는 실제로 얼마나 작동하는가? 어디까지 높일 수 있는가?**

v1을 점검해 보니 이런 점이 드러났습니다.
- 위기 감지는 정규식 26개였습니다. 돌려 말한 위험 표현을 대부분 놓쳤고, "자살골", "죽고 싶을 만큼 웃겼어" 같은 일상 표현에는 보호자 '긴급' 알림을 보냈습니다.
- 학대 노출을 따로 다루지 않았습니다.
- 만 14세 미만 법정대리인 동의를 아이 본인이 체크했습니다.
- 보호자 화면으로 가는 글의 원문 유출을 검사하는 장치가 약했습니다.

## 변경 항목

| # | 영역 | v1 | v2 |
|---|---|---|---|
| 1 | 위기 신호 단계 | 3단계(없음·위험·긴급) | 5단계(없음·관찰·위험·긴급·보호). 관찰은 보호자 알림 없이 기록만 하고, 보호는 학대 노출 시 보호자 자동 알림을 막습니다 |
| 2 | 위기 감지 | 정규식 26개 | 정규화(초성·숫자 끼우기·띄어쓰기·오타) + 범주별 신호 8종(직접·간접·무망감·치료 거부·수단·학대·과거·외로움) + 오탐 억제 10종(과장·게임·교육·부정문·제3자·사과 초성·병원 단어 등) |
| 3 | 대화 맥락 | 한 문장만 봄 | 직전 3개 메시지로 상향(무망감 뒤 "다 그만하고 싶어", 죽음 소망 뒤 장소 질문)과 하향(숙제·게임 이야기) |
| 4 | 애매한 문장 | 없음 | 응답이 스트리밍되는 동안 LLM이 다시 판정합니다. 상향만 하고 시간 제한이 있습니다 |
| 5 | 아이에게 보이는 안내 | 단계와 무관한 고정 문구 | 단계별 안내. 보호자에게 무엇을 알렸는지 아이에게 투명하게 표시하고, 비밀 약속은 하지 않습니다 |
| 6 | 보호자 알림 | 고정 문구 | 사실만 알리고 대처 안내(의료진·109·119)를 붙입니다. 대화 원문은 보내지 않습니다 |
| 7 | 반복 신호 | 없음 | 72시간 안에 관찰 신호가 3번 이상이면 "보호자에게 알려도 될까?"라고 아이에게 묻습니다(아이 동의 기반 공유) |
| 8 | 건강한 관계 | 없음 | 프롬프트 원칙, 응답 가드(독점·보호자 비밀 강요·연애·'나는 사람' 문장 제거), 사용 리듬(늦은 밤·긴 대화), 하루 1개 사람 연결 미션 |
| 9 | AI 고지 | 없음 | 대화창 'AI 친구' 표시와 상시 안내. AI가 만든 그림에는 'AI로 그렸어요'를 표시합니다(인공지능기본법 투명성 의무) |
| 10 | 비용·남용 | 없음 | 하루 AI 호출·그림 상한(넘으면 비용 0의 오프라인 답변·번들 그림), 아이 1명당 대화 속도 제한 |
| 11 | 배포 | 해커톤 계정(현재 중단) | AWS: CloudShell 한 번 실행으로 재현되는 배포. CloudFront HTTPS, 서버는 CloudFront 접근만 허용, IMDSv2·암호화. AWS 없이: 18번 |
| 12 | 보안 정리 | 문서에 데모 비밀번호 공개 | 삭제. 배포 때 새 비밀번호를 SSM SecureString으로 생성합니다 |
| 13 | 평가 체계 | 없음 | 라벨 기준서, 개발셋과 독립 평가셋 분리, `npm run eval:safety`로 v1·v2 비교 |
| 14 | 보호자 질문 답변(RAG) 최신성 | 요약을 S3에 쓰기만 하고 KB 색인을 시작하지 않음 → 처음 색인된 문서만 검색 | 새벽 배치 뒤 새 요약이 있으면 KB 재색인 시작 |
| 15 | 접근성 | 글자 입력만 가능 | 음성으로 말하기(브라우저 음성 인식), 베디 답장 소리로 듣기. 손이 불편한 아이·저학년·시력이 약한 아이 |
| 16 | 측정 경로 | — | 배포된 서비스에서 규칙만 / 규칙+LLM 판정 지표를 내는 관리자 경로(`/api/admin/safety-eval`, `deploy/aws/run-eval.sh`) |
| 17 | 응답 안전 필터 | Bedrock Guardrails에만 의존. 앱 자체의 응답 검사는 없음 | 문장 단위 출력 필터를 모든 모델 경로에 적용합니다. 개인정보(전화·이메일·주민번호 형식)는 가리고, 약 복용·중단 지시와 위험 방법 설명, 관계 규칙 위반 문장은 바꿉니다. 문장이 화면에 나가기 **전에** 검사합니다 |
| 18 | AWS 없이 배포 | AWS 전용 | Render + Claude API 배포(`render.yaml`, `deploy/render/README.md`). 계정은 디스크의 bcrypt 해시 파일로, 보호자 질문 검색은 서버 안 요약 검색으로, 새벽 배치는 서버 안 스케줄러로 대신합니다. 심사·시연 계정은 환경 변수 비밀번호로 시작할 때 만듭니다 |
| 19 | Claude API 연동 | 없음 | Claude Haiku 5.5 공급자. 용도별 effort·thinking, 재시도, 스트림 정지 감시. 모델이 거절하면 아이에게 안전한 안내 문장을 보여 주고, 안전 재판정이 거절되면 '관찰'로 기록합니다 |
| 20 | 미션 생성 장애 | LLM 답에 JSON이 없으면 오류가 위로 올라가 미션 화면과 보호자 리포트까지 실패 | 생성 실패는 규칙 기반 미션으로 대체 |
| 21 | 날짜 기준 | 서버가 UTC라 하루가 오전 9시(KST)에 바뀌고, 05:00 새벽 배치가 전날 날짜로 돎 | 컨테이너 시간대를 Asia/Seoul로 고정 |
| 22 | 로컬 저장 안정성 | 파일을 통째로 덮어써 쓰는 도중 꺼지면 깨질 수 있음. 같은 파일을 여는 두 저장소(`memory-post.json`)가 서로의 쓰기를 덮어씀 | 임시 파일에 쓴 뒤 교체, 파일당 메모리 맵 하나를 공유, 종료 신호 때 남은 쓰기 저장 |
